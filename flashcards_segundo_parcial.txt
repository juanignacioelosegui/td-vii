¿Cuáles son las 3 componentes de la Tríada CIA en seguridad de bases de datos?	<b>Confidencialidad</b> (solo acceden los autorizados), <b>Integridad</b> (datos correctos y no alterados sin autorización), <b>Disponibilidad</b> (datos accesibles cuando se necesitan).	seguridad
¿Qué es el control de acceso DAC (Discretionary Access Control)?	El <b>dueño del recurso</b> decide quién tiene acceso. El propietario otorga permisos a otros usuarios a discreción. Ejemplo: GRANT/REVOKE en SQL.	seguridad
¿Qué es el control de acceso MAC (Mandatory Access Control)?	El acceso lo determina el <b>sistema</b> según niveles de seguridad (etiquetas/clasificaciones), no el dueño del recurso. Los usuarios no pueden modificar los permisos.	seguridad
¿Qué es RBAC (Role-Based Access Control)?	Los permisos se asignan a <b>roles</b>, y los usuarios se asignan a roles. Simplifica la administración: en vez de dar permisos usuario por usuario, se gestionan por rol.	seguridad
¿Cuáles son las responsabilidades principales del DBA en seguridad?	Crear cuentas/perfiles, otorgar/revocar privilegios, asignar niveles de seguridad, auditoría, y garantizar la integridad y disponibilidad de los datos.	seguridad
¿Qué es el control de inferencia en seguridad de BD?	Mecanismo para evitar que usuarios deduzcan información confidencial a partir de datos que sí tienen acceso. Ej: si se puede consultar promedio de sueldos de un departamento con 1 persona, se infiere el sueldo exacto.	seguridad
¿Qué diferencia hay entre cifrado simétrico y asimétrico?	<b>Simétrico:</b> misma clave para cifrar y descifrar (más rápido). <b>Asimétrico:</b> par de claves pública/privada (más seguro para intercambio).	seguridad
¿Cuáles son las 3 propiedades fundamentales de una función hash criptográfica?	1) <b>Determinística</b>: misma entrada → misma salida siempre. 2) <b>No reversible</b>: no se puede obtener la entrada desde la salida. 3) <b>Computacionalmente inviable</b> encontrar colisiones (dos entradas con misma salida).	password-hashing
¿Qué es una Rainbow Table y cómo se usa para atacar passwords?	Tabla precalculada que mapea <b>hashes a sus textos planos</b> correspondientes. Se compara el hash robado contra la tabla para encontrar la contraseña original sin fuerza bruta en tiempo real.	password-hashing
¿Qué es el salting en password hashing y por qué es importante?	Agregar un valor aleatorio único (<b>salt</b>) a cada contraseña antes de hashearla. Así, dos usuarios con la misma contraseña producen hashes distintos, y las rainbow tables se vuelven inútiles.	password-hashing
¿Cuáles son las 4 V's de Big Data?	<b>Volumen</b> (cantidad masiva), <b>Variedad</b> (datos estructurados, semi y no estructurados), <b>Velocidad</b> (ritmo de generación y procesamiento), <b>Veracidad</b> (calidad y confiabilidad de los datos).	big-data
¿Qué diferencia hay entre escalabilidad vertical y horizontal?	<b>Vertical:</b> agregar más recursos (CPU, RAM) a un mismo servidor. <b>Horizontal:</b> agregar más servidores/nodos al sistema. Big Data requiere escalabilidad horizontal.	big-data
¿Qué es el sharding (partición horizontal)?	Dividir los datos de una tabla entre múltiples nodos/servidores, donde cada nodo almacena un subconjunto de las filas. Permite distribuir carga y escalar horizontalmente.	big-data
¿Qué son las réplicas pasivas en tolerancia a fallos?	Copias redundantes de los datos en otros nodos. Si un nodo falla, las réplicas permiten continuar operando sin pérdida de datos.	big-data
¿Qué es la tolerancia a fallos humanos (human fault tolerance)?	Capacidad del sistema de recuperarse de errores cometidos por personas (ej: un deploy malo, un DELETE sin WHERE). Se logra con inmutabilidad de datos y capacidad de recomputar.	big-data
¿Cuál es la ecuación fundamental de un sistema de datos según first principles?	<b>query = function(all data)</b><br>Una consulta es una función aplicada sobre todos los datos disponibles.	big-data
¿Qué es "Data" según los first principles de Big Data (Marz)?	Información verdadera que <b>no puede ser derivada</b> de otros elementos. Son los "axiomas" del sistema. Ejemplo: los eventos crudos de un usuario.	big-data
¿Qué diferencia hay entre un Data Warehouse (OLAP) y una BD transaccional (OLTP)?	<b>OLTP:</b> optimizada para operaciones transaccionales (INSERT, UPDATE, DELETE) de muchos usuarios concurrentes. <b>OLAP (DWH):</b> optimizada para consultas analíticas complejas sobre grandes volúmenes históricos.	integracion-datos
¿Qué es la Arquitectura Medallion y cuáles son sus capas?	Patrón de organización de datos en un Data Lake con 3 capas:<br><b>Bronze:</b> datos crudos sin procesar<br><b>Silver:</b> datos limpiados y conformados<br><b>Gold:</b> datos agregados/listos para consumo analítico.	integracion-datos
¿Qué es un Star Schema y cuáles son sus componentes?	Modelo de datos para DWH con:<br><b>Fact table:</b> tabla central con métricas/medidas y FKs (ej: ventas, montos)<br><b>Dimension tables:</b> tablas descriptivas conectadas a la fact (ej: producto, cliente, tiempo).	integracion-datos
¿Cuál es la diferencia entre SCD Tipo 1 y SCD Tipo 2?	<b>Tipo 1:</b> se sobreescribe el valor anterior (se pierde historial).<br><b>Tipo 2:</b> se agrega una nueva fila con fechas de vigencia (valid_from, valid_to), conservando el historial completo.	integracion-datos
¿Qué diferencia hay entre Schema on Write y Schema on Read?	<b>Schema on Write:</b> los datos deben cumplir un esquema al momento de cargarse (DWH tradicional).<br><b>Schema on Read:</b> los datos se almacenan crudos y el esquema se aplica al momento de leerlos (Data Lake).	integracion-datos
¿Qué es una arquitectura Fully Incremental?	Arquitectura donde cada nuevo dato actualiza incrementalmente el estado actual. Se mantiene solo el estado más reciente. Problema: si hay un bug, no se puede reconstruir el estado porque los datos originales se perdieron.	arquitecturas-datos
¿Qué es Event Sourcing?	Arquitectura que almacena <b>todos los eventos/cambios</b> como secuencia inmutable. El estado actual se deriva recomputando todos los eventos. Ventaja: historial completo y capacidad de recomputar. Desventaja: latencia de recompute.	arquitecturas-datos
¿Qué es consistencia fuerte (strong consistency)?	Después de una escritura, <b>toda</b> lectura subsiguiente devuelve el valor actualizado. Todos los nodos ven los mismos datos al mismo tiempo.	arquitecturas-datos
¿Qué es consistencia eventual (eventual consistency)?	Si no se hacen más escrituras, eventualmente <b>todas las réplicas</b> convergerán al mismo valor. No garantiza que una lectura inmediata devuelva lo más reciente.	arquitecturas-datos
¿Qué es la consistencia RYOW (Read Your Own Writes)?	Garantiza que un usuario siempre ve <b>sus propias escrituras</b>. Otro usuario podría ver datos desactualizados, pero cada uno ve al menos lo que él mismo escribió.	arquitecturas-datos
¿Qué dice el Teorema CAP?	En un sistema distribuido, solo se pueden garantizar <b>2 de 3</b> propiedades simultáneamente:<br><b>C</b>onsistency (todos ven los mismos datos)<br><b>A</b>vailability (toda request recibe respuesta)<br><b>P</b>artition tolerance (funciona pese a fallos de red).	arquitecturas-datos
¿Por qué en la práctica se debe elegir entre C y A en el Teorema CAP?	Porque las <b>particiones de red son inevitables</b> en sistemas distribuidos (P es obligatorio). Entonces la elección real es: ante una partición, ¿priorizamos consistencia (rechazando requests) o disponibilidad (respondiendo con datos potencialmente desactualizados)?	arquitecturas-datos

¿Qué dimensiones se evalúan en Data Quality?	<b>Unicidad</b> (sin duplicados), <b>No nulos</b> (campos obligatorios completos), <b>Rangos</b> (valores dentro de límites válidos), <b>Referencias</b> (integridad referencial), <b>Frescura</b> (datos actualizados a tiempo).	calidad-gobernanza
¿Qué componentes incluye Data Governance?	<b>Catálogo de datos</b> (inventario de datasets y metadatos), <b>Lineage</b> (rastreo de origen y transformaciones), <b>Freshness</b> (monitoreo de actualización), <b>Ownership</b> (responsables definidos por cada dataset).	calidad-gobernanza
¿Qué es un DAG en el contexto de orquestación de datos?	<b>Directed Acyclic Graph</b>: grafo dirigido sin ciclos que define las dependencias entre tareas de un pipeline. Cada nodo es una tarea y las aristas indican precedencia.	calidad-gobernanza
¿Qué es la idempotencia en pipelines de datos y por qué importa?	Una operación es idempotente si ejecutarla <b>múltiples veces produce el mismo resultado</b> que ejecutarla una vez. Importa porque permite reintentar tareas fallidas sin generar datos duplicados o corruptos.	calidad-gobernanza
¿Qué es un backfill en orquestación de datos?	Proceso de <b>ejecutar retroactivamente</b> un pipeline para fechas/períodos pasados. Se usa cuando se agrega una nueva transformación o se corrige un bug y hay que reprocesar datos históricos.	calidad-gobernanza
¿Cuáles son los componentes del stack moderno de datos visto en la materia?	<b>PostgreSQL</b> (base de datos), <b>dbt-core</b> (transformación), <b>Dagster</b> (orquestación), <b>Metabase</b> (visualización/BI).	calidad-gobernanza
En SQL Server, ¿qué diferencia hay entre Scan y Seek?	<b>Scan:</b> recorre <b>toda</b> la estructura (tabla o índice) secuencialmente.<br><b>Seek:</b> usa el índice para ir <b>directamente</b> a las filas que cumplen la condición. Seek es mucho más eficiente para consultas selectivas.	optimizacion-sql
¿Cuáles son los operadores de acceso a datos en SQL Server según la estructura?	<b>Heap:</b> Table Scan (solo scan, no seek).<br><b>Clustered Index:</b> Clustered Index Scan / Clustered Index Seek.<br><b>Nonclustered Index:</b> Index Scan / Index Seek.	optimizacion-sql
¿Cuáles son los dos operadores de agregación en SQL Server?	<b>Stream Aggregate:</b> requiere datos ordenados (usa índice o Sort previo). Siempre usado para scalar aggregates (sin GROUP BY).<br><b>Hash Aggregate (Hash Match):</b> para datos no ordenados, pocos grupos, tablas grandes.	optimizacion-sql
¿Qué es un Scalar Aggregate vs un Vector Aggregate?	<b>Scalar Aggregate:</b> función de agregación sobre <b>toda la tabla</b> (sin GROUP BY), devuelve un único valor. Ej: SELECT AVG(precio) FROM productos.<br><b>Vector Aggregate:</b> agrega <b>por grupo</b> (con GROUP BY), devuelve un valor por grupo.	optimizacion-sql
¿Cuándo elige SQL Server un Stream Aggregate vs Hash Aggregate?	<b>Stream Aggregate:</b> cuando los datos ya vienen ordenados (por un índice) o se introduce un Sort explícito.<br><b>Hash Aggregate:</b> datos no ordenados, no necesita ordenarlos, y la cardinalidad se estima en pocos grupos.	optimizacion-sql
¿Qué operador puede implementar DISTINCT en SQL Server?	DISTINCT puede implementarse con <b>Stream Aggregate</b>, <b>Hash Aggregate</b>, o un operador <b>Distinct Sort</b>.	optimizacion-sql
¿Cuáles son los 3 algoritmos de JOIN en SQL Server?	<b>Nested Loops Join</b>, <b>Merge Join</b>, y <b>Hash Join</b>.	optimizacion-sql
¿Cuándo es más efectivo un Nested Loops Join?	Cuando el <b>outer input es pequeño</b> y el <b>inner input es grande pero indexado</b>. Es el único join que no requiere equi-join (puede usar cualquier predicado).	optimizacion-sql
¿Cuáles son las características del Merge Join?	Requiere que <b>ambas tablas estén ordenadas</b> por la columna de join. Óptimo con clustered/covering index en ambas. Solo soporta <b>equi-join</b>. Eficiente para tablas <b>grandes</b>.	optimizacion-sql
¿Cuáles son las características del Hash Join?	Inner table: <b>no necesita índice</b>. Útil para tablas de <b>cualquier tamaño</b>. No requiere datos preordenados. Solo soporta <b>equi-join</b>. Óptimo: outer table pequeña, inner table grande.	optimizacion-sql
¿Qué hace el operador Compute Scalar en un plan de ejecución SQL Server?	Realiza <b>cálculos o conversiones de tipo</b> sobre los datos. Ej: COUNT(*) retorna int pero COUNT_BIG(*) retorna bigint; Compute Scalar convierte el tipo.	optimizacion-sql
¿Qué hace el operador Filter en un plan de ejecución?	Aplica una condición de <b>filtrado posterior</b> a la agregación, típicamente para cláusulas <b>HAVING</b>. Se ejecuta después del aggregate.	optimizacion-sql
Resumen comparativo de JOINs: ¿qué requiere cada uno en índices, tamaño, presorted, y tipo de join?	<b>Hash:</b> índice opcional, any size, no presorted, equi-join.<br><b>Merge:</b> ambas deben tener índice, large tables, sí presorted, equi-join.<br><b>Nested Loop:</b> inner debe tener índice, small tables, presorted opcional, cualquier tipo de join.	optimizacion-sql
¿Qué es la anonimización de datos y cuál es su objetivo?	Proceso de proteger datos sensibles para garantizar la <b>privacidad de las personas</b> y cumplir con leyes como la <b>Ley 25.326</b> de Protección de Datos Personales. Garantiza que información personal identificable no sea revelada.	anonimizacion
¿Qué es la técnica de Perturbación en anonimización?	Alterar ligeramente los valores de los datos. Ej: agregar <b>ruido aleatorio</b> a ingresos o edades, manteniendo la utilidad estadística pero protegiendo valores individuales.	anonimizacion
¿Qué es K-anonimato?	Asegurar que cada registro no sea distinguible de al menos <b>k-1 otros registros</b>. Se modifican los datos para que cada combinación de atributos cuasi-identificadores aparezca al menos k veces.	anonimizacion
¿Qué es L-diversidad y qué problema resuelve del K-anonimato?	Garantizar que en cada grupo k-anónimo haya al menos <b>l valores "bien representados"</b> para los atributos sensibles. Resuelve el problema de que un grupo k-anónimo podría tener todos el mismo valor sensible (ej: todos con misma enfermedad).	anonimizacion
¿Por qué la documentación del proceso de anonimización debe conservarse de forma segura?	Porque la revelación de los <b>parámetros</b> utilizados en la anonimización puede facilitar la <b>reidentificación</b> de los datos anonimizados.	anonimizacion
Nombrá 3 herramientas de anonimización de datos vistas en la materia.	<b>Amnesia:</b> código abierto, OpenAIRE, k-anonimato y l-diversidad.<br><b>ARX:</b> código abierto, soporta k-anonimato, l-diversidad, t-closeness, privacidad diferencial.<br><b>sdcMicro:</b> paquete R, anonimización de microdatos censales/encuestas.	anonimizacion
¿Qué es la Arquitectura Lambda?	Arquitectura orientada a resolver los problemas de fully incremental y event sourcing para casos no triviales. Combina procesamiento <b>batch y real-time</b> para lograr data freshness con las ventajas del reprocesamiento batch.	lambda
¿Cuáles son las 3 capas de la Arquitectura Lambda?	<b>Batch Layer:</b> construye batch views a partir de todo el master dataset.<br><b>Serving Layer:</b> sirve/indexa las batch views para consultas.<br><b>Speed Layer:</b> construye real-time views con datos que aún no están en las batch views.	lambda
¿Cuáles son las 3 ecuaciones que resumen la Arquitectura Lambda?	1) <b>batch view = function(all data)</b><br>2) <b>realtime view = function(realtime view, new data)</b><br>3) <b>query = function(batch view, realtime view)</b>	lambda
¿Qué es un Batch View en la Arquitectura Lambda?	Vista <b>pre-computada</b> sobre todo el master dataset. Se genera periódicamente procesando todos los datos. Alta latencia de generación pero resultados precisos.	lambda
¿Por qué se necesita una Speed Layer en la Arquitectura Lambda?	Porque crear batch views es una operación de <b>alta latencia</b>. Mientras se computa, llegan datos nuevos que no están representados. La speed layer incorpora esos datos recientes mediante <b>real-time views</b>.	lambda
¿Qué es el Master Dataset en la Arquitectura Lambda?	Es el <b>core</b> de la arquitectura. Es la <b>source of truth</b> (fuente de verdad). Si se perdieran todos los datos de serving y speed layer, todo se puede reconstruir desde el master dataset.	lambda
¿Cuáles son las 3 propiedades clave de los datos en el Master Dataset?	<b>Crudeza (rawness):</b> datos lo más crudos posible, sin procesar.<br><b>Inmutabilidad:</b> no hay updates ni deletes, solo appends.<br><b>Perpetuidad:</b> los datos se conservan indefinidamente.	lambda
¿Por qué es importante la crudeza (rawness) de los datos en el master dataset?	Datos más crudos permiten <b>derivar más información</b> en el futuro, incluso información que hoy no se sabe que se necesita. Los algoritmos de procesamiento pueden cambiar sin afectar los datos originales.	lambda
¿Qué es la normalización semántica y por qué es riesgosa para el master dataset?	Proceso de reorganizar información con formato libre en una forma estructurada. Es riesgosa porque implica <b>eliminar cualidades del dato</b> que podrían importar en el futuro. Se prefiere almacenar datos crudos.	lambda
¿Por qué la inmutabilidad del master dataset hace al sistema tolerante a fallos humanos?	Porque al no haber updates ni deletes, un error humano no destruye datos. Si ocurre un error, se puede <b>recomputar</b> el master dataset. Además simplifica la carga: estructuras append-only con archivos planos.	lambda
¿Cuál es la diferencia entre Datos, Información, Consultas y Vistas según la Arquitectura Lambda?	<b>Datos:</b> axiomas no derivables de otros elementos.<br><b>Información:</b> conjunto total de conocimiento relevante.<br><b>Consultas:</b> preguntas que se hacen a la información.<br><b>Vistas:</b> información derivada de los datos base, orientada a consultas.	lambda
¿Qué son los serialization frameworks y cuáles son los 3 principales?	Herramientas para serializar objetos en bytes desde cualquier lenguaje y deserializarlos en otro. Proveen definición de esquemas y versionado. Los 3 principales: <b>Thrift</b>, <b>Protocol Buffers</b>, y <b>Avro</b>.	lambda-almacenamiento
¿Qué es el formato Avro y cuáles son sus características principales?	Formato de serialización: almacena <b>esquema junto al mensaje</b> (en JSON), aporta <b>compresión</b>, organiza datos en <b>filas (row-oriented)</b>, soporta estructuras complejas (arrays, maps), bloques de tamaño fijo.	lambda-almacenamiento
¿Cómo se organiza un archivo Avro internamente?	Dos partes:<br><b>Header:</b> magic number (4 bytes), esquema (JSON), metadata, marcador de sincronización (16 bytes).<br><b>Bloques de datos:</b> cada uno con cantidad de registros, tamaño en bytes, objetos serializados, marcador de sincronización.	lambda-almacenamiento
¿Qué es el formato Parquet y en qué se diferencia de Avro?	Formato <b>columnar</b> (column-oriented) vs Avro que es row-oriented. Parquet ofrece mejor compresión por columna, encoding específico por columna, <b>predicate pushdown</b>, y es más eficiente para consultas analíticas que solo leen algunas columnas.	lambda-almacenamiento
¿Qué es predicate pushdown en Parquet?	Acercar la lógica de filtrado al <b>origen de los datos</b>. Se ejecutan filtros directamente en el origen, evitando transferir todos los datos por la red al motor de procesamiento. Ahorra tiempo y reduce tráfico.	lambda-almacenamiento
¿Cómo se organiza un archivo Parquet internamente?	Cuatro partes:<br>1) <b>Magic number</b> (4 bytes)<br>2) Metadata de <b>row groups</b> con offsets<br>3) <b>Column chunks</b> (datos columna por columna por row group)<br>4) <b>Footer</b> con esquema, info de row groups, encoding y ubicación de chunks.	lambda-almacenamiento
¿Cuándo conviene usar Avro vs Parquet?	<b>Avro (row-oriented):</b> para escribir/leer filas completas, streaming, carga de datos.<br><b>Parquet (column-oriented):</b> para consultas analíticas que leen pocas columnas de muchas filas, mejor compresión, predicate pushdown.	lambda-almacenamiento
¿Qué es un File System Distribuido y qué garantías provee?	Múltiples soportes físicos detrás de un único file system lógico. Garantías: <b>escalabilidad</b>, <b>high availability</b>, <b>paralelización de lecturas</b>, y <b>redundancia</b>.	lambda-almacenamiento
¿Qué es HDFS y cuáles son sus características?	<b>Hadoop Distributed File System</b>: filesystem distribuido diseñado para Hadoop. Open source (Java), optimizado para archivos muy grandes, maneja grandes volúmenes.	lambda-almacenamiento
¿Cuáles son los 3 componentes principales de Hadoop?	<b>HDFS</b> (Hadoop Distributed File System) para almacenamiento, <b>MapReduce</b> para procesamiento distribuido, y <b>YARN</b> (Yet Another Resource Negotiator) para gestión de recursos.	lambda-almacenamiento
¿Cuál es la principal ventaja de Hadoop respecto al hardware?	Diseñado para ejecutar sobre <b>hardware sencillo, normal y corriente</b> (commodity hardware). Acerca el procesamiento al lugar donde están almacenados los datos, en vez de mover los datos al procesamiento.	lambda-almacenamiento
¿Por qué en Hadoop se prefiere mover el procesamiento a los datos y no al revés?	Mover el procesamiento es mucho más <b>rápido, fácil y eficiente</b> que mover grandes cantidades de datos, que pueden producir altas latencias y congestión en la red.	lambda-almacenamiento
¿Qué relación hay entre Data Lake y Data Warehouse?	<b>Data Lake:</b> almacena datos crudos sin esquema predefinido (schema on read), acepta cualquier formato.<br><b>Data Warehouse:</b> almacena datos estructurados y procesados con esquema definido (schema on write), optimizado para consultas analíticas.	integracion-datos
¿Qué es una Fact Table en un Star Schema?	Tabla central que contiene las <b>métricas/medidas numéricas</b> del negocio (ej: monto de venta, cantidad) y las <b>foreign keys</b> a las dimensiones. Suele tener muchas filas.	integracion-datos
¿Qué es una Dimension Table en un Star Schema?	Tabla descriptiva que provee <b>contexto</b> a las medidas de la fact table. Contiene atributos como nombre de producto, categoría, fecha, nombre de cliente. Suele tener pocas filas pero muchas columnas.	integracion-datos
¿Qué es Data Lineage?	Rastreo del <b>origen y las transformaciones</b> que sufren los datos desde su fuente hasta su destino final. Permite entender de dónde viene cada dato y cómo fue procesado.	calidad-gobernanza
¿Qué es un catálogo de datos?	Inventario centralizado de todos los datasets, tablas y recursos de datos de una organización, incluyendo <b>metadatos</b>, descripciones, dueños, y relaciones entre datasets.	calidad-gobernanza
¿Qué es consistencia de sesión?	Garantiza consistencia dentro de una <b>misma sesión</b> de usuario. Dentro de la sesión se ve RYOW (Read Your Own Writes), pero entre sesiones diferentes puede haber inconsistencia.	arquitecturas-datos
¿Qué tecnologías se usan para implementar la Arquitectura Lambda?	Entornos de cómputo paralelizable (batching y streaming), sistemas de almacenamiento distribuido (HDFS, NoSQL), frameworks de serialización (Avro, Parquet), y sistemas de colas distribuidas (asincrónicas).	lambda
¿Por qué el Master Dataset es la única parte de la Arquitectura Lambda que debe estar absolutamente protegida?	Porque es el <b>source of truth</b>. Las batch views de la serving layer y las real-time views de la speed layer se pueden <b>reconstruir</b> desde el master dataset. Si se pierde el master dataset, se pierde todo.	lambda
¿Qué es el Merge Join y cuándo requiere un Sort previo?	Merge Join requiere ambas entradas ordenadas por la columna de join. Si ya hay un <b>clustered index o covering index</b> que provea orden, no necesita Sort. Si no, SQL Server introduce un <b>Sort operator</b> explícito.	optimizacion-sql
¿Qué dos decisiones debe tomar el optimizador de consultas respecto a JOINs?	1) La selección del <b>orden de las juntas</b> (qué tabla va primero).<br>2) La selección del <b>algoritmo de junta</b> (Nested Loops, Merge o Hash).	optimizacion-sql
¿Cuáles son las 8 dimensiones de calidad de datos?	1) <b>Precisión</b> (cercano a la realidad)<br>2) <b>Completitud</b> (sin NULLs indebidos)<br>3) <b>Consistencia</b> (reglas de negocio se mantienen entre tablas)<br>4) <b>Puntualidad</b> (disponible cuando se necesita)<br>5) <b>Validez</b> (tipo correcto, FK válidas)<br>6) <b>Unicidad</b> (sin duplicados)<br>7) <b>Conformidad</b> (formato correcto)<br>8) <b>Accesibilidad</b> (disponible para interesados)	calidad-gobernanza
¿Qué es la Precisión como dimensión de calidad de datos? Dar un ejemplo.	Qué tan <b>cercano a la realidad</b> es el dato. Ej: "Perezz" en vez de "Perez" tiene formato correcto (es un string) pero <b>no se corresponde con la realidad observable</b>.	calidad-gobernanza
¿Qué es la Consistencia como dimensión de calidad de datos?	Las <b>reglas de negocio se mantienen</b> entre tablas. Los datos tienen coherencia. Ej: la dirección de una empresa en la tabla de empleados debe coincidir con la dirección en la tabla de empresas.	calidad-gobernanza
¿Qué es la Validez como dimensión de calidad de datos?	Revisión de <b>tipo de dato</b> y <b>claves foráneas</b>. Ej: un campo "Total de gastos" con valor "a" no es válido; una FK con código 99 que no existe en la tabla referenciada tampoco.	calidad-gobernanza
¿Cuál es el ciclo de vida del dato?	<b>Create → Store → Use → Share → Archive → Destroy</b>. Representa las etapas por las que pasa un dato desde su creación hasta su eliminación.	calidad-gobernanza
¿Qué es la Gobernanza de datos?	Capacidad de una organización de <b>asegurar que los datos sean de alta calidad</b>. Implica: definir responsables (data stewards), políticas de almacenamiento/backup/protección, normas de uso, y procedimientos de auditoría.	calidad-gobernanza
¿Qué es la Observabilidad de datos?	Comprensión que tiene una organización respecto a la <b>salud y desempeño de los datos</b>. Se logra mediante: monitoreo automatizado, análisis de causa raíz (RCA), y data lineage. Objetivo: <b>prevenir, detectar y resolver anomalías</b> lo antes posible.	calidad-gobernanza
¿Qué diferencia hay entre Data Governance Lead y Data Steward?	<b>Data Governance Lead:</b> fija la <b>estrategia</b> de gobernanza de la organización.<br><b>Data Steward:</b> ejecuta las <b>tareas diarias</b> de gobernanza (implementación operativa).	calidad-gobernanza
¿Qué es PII (Personally Identifiable Information)?	Información que permite <b>identificar directamente</b> a un individuo. Ejemplos: nombre, dirección, CUIT, teléfono, e-mail. Las organizaciones deben cumplir normativas (GDPR, CCPA) para protegerla.	privacidad-compliance
¿Qué es un Data Catalog y para qué sirve?	Metadatos curados sobre <b>qué datos</b> tiene la organización, <b>quién</b> los usa y <b>dónde</b> están. Sirve para: gobernanza/compliance, rastrear PII, saber quién tiene acceso a qué datos, y responder dónde buscar datos.	privacidad-compliance
¿Qué es Data Discovery y en qué se diferencia de un Data Catalog?	Data Discovery muestra el estado <b>actual y en tiempo real</b> de los datos (dinámico), mientras que el catálogo muestra el estado "ideal catalogado" (estático). Discovery permite <b>democratización del dato</b>.	privacidad-compliance
¿Cuáles son los 4 niveles de madurez de datos en una organización?	1) <b>Data reactive:</b> nadie accede ni usa datos<br>2) <b>Data scaling:</b> pocos tienen skills para analizar<br>3) <b>Data progressive:</b> al menos 1 empleado data-fluent por equipo<br>4) <b>Data fluent:</b> todos saben cómo acceder a los datos que necesitan	privacidad-compliance
¿Qué establece la Ley 25.326 de Protección de Datos Personales (Argentina)?	Los ciudadanos pueden solicitar que sus datos: no sean usados sin consentimiento, les informen qué datos tienen, sean corregidos/actualizados, sean suprimidos, y sean guardados confidencialmente. Organismo: <b>AAIP</b>.	privacidad-compliance
¿Qué son GDPR y CCPA?	<b>GDPR</b> (2016): Reglamento General de Protección de Datos de la <b>Unión Europea</b>.<br><b>CCPA</b> (2018): California Consumer Privacy Act de <b>EEUU</b>. Ambas regulan la protección de datos personales de ciudadanos.	privacidad-compliance
¿Qué son los datos sensibles prohibidos según la ley argentina?	No puede haber registros referidos a: <b>origen racial/étnico</b>, opiniones políticas, convicciones religiosas/filosóficas/morales, afiliación sindical, o datos de <b>salud y vida sexual</b>.	privacidad-compliance
¿Qué es Data Literacy?	Habilidad de <b>leer, escribir y comunicar</b> sobre datos de manera que genere valor para la organización. Si no se entiende el valor de los datos, no se puede entender el valor de la calidad de datos.	privacidad-compliance
¿Qué es Swampification en el contexto de datos?	Cuando se depende demasiado de un data engineer/scientist para saber dónde residen datos, quiénes son los stakeholders y cómo podrían cambiar. Los datos se <b>"pantanizan"</b>: la curva de aprendizaje es tan empinada que nadie puede trabajar.	privacidad-compliance
¿Qué es SQL Injection?	Ataque que se aprovecha de que servicios/aplicaciones usan <b>input externo como parte de sus consultas SQL</b>. Orientado a obtener información no autorizada, alterar información o destruirla. Se previene sanitizando inputs.	seguridad
¿Cuáles son las 4 estrategias/técnicas de seguridad de la información?	1) <b>Autenticación:</b> verificación de identidad<br>2) <b>Control de acceso:</b> verificación de permisos<br>3) <b>Encriptación:</b> oscurecimiento de datos<br>4) <b>Firewalls/sistemas de detección:</b> prevención de acceso a redes	seguridad
¿Cómo se combinan DAC y MAC en la práctica?	Primero se aplican los <b>privilegios discrecionales (DAC)</b> (tiene o no tiene permiso), y además se verifica que el <b>nivel de seguridad del usuario</b> sea compatible con el <b>nivel del dato</b> al que quiere acceder (MAC).	seguridad
En RBAC, ¿cuál es la jerarquía de objetos sobre los que se controla acceso?	1) <b>Base de datos:</b> conjunto de esquemas, un sistema de permisos<br>2) <b>Esquema:</b> separación lógica, conjunto de objetos<br>3) <b>Objetos atómicos:</b> tablas, vistas, funciones, índices	seguridad
¿Qué es el superusuario (DBA) en seguridad de BD?	Cuenta especial con <b>facultades que no tienen las demás cuentas</b>: puede otorgar y revocar privilegios para cuentas individuales o grupos. Es el administrador central responsable de la seguridad.	seguridad
¿Cuáles son los 3 pasos del proceso de salting?	1) Para cada contraseña, se genera un <b>string aleatorio (salt)</b><br>2) Se <b>almacena el salt</b> junto con la información de la cuenta<br>3) Al hashear, se concatena <b>contraseña + salt</b> y se aplica el hash a esa concatenación	password-hashing
¿Por qué el password hashing protege incluso contra superusuarios?	Porque las contraseñas se almacenan como <b>hashes, no en texto plano</b>. Ni siquiera un DBA con acceso completo a la base puede ver las contraseñas originales, ya que el hash <b>no es reversible</b>.	password-hashing
Describí la evolución del sistema SuperWebAnalytics hacia Big Data (6 etapas).	1) RDBMS simple<br>2) Cola + worker (back-pressure)<br>3) Múltiples workers + load balancer<br>4) <b>Sharding</b> de la DB (partición horizontal)<br>5) <b>Réplicas pasivas</b> (tolerancia a fallos de disco)<br>6) Necesidad de <b>human fault tolerance</b> (bugs corrompen datos)	big-data
¿Cuáles son los requerimientos no funcionales deseables de un sistema de datos?	1) <b>Tolerancia a fallos</b><br>2) <b>Escalabilidad</b><br>3) <b>Extensibilidad</b><br>4) <b>Mantenibilidad</b><br>5) <b>Baja latencia</b><br>6) <b>Soporte para consultas específicas</b>	big-data
¿Cuáles son las ventajas de Schema-on-Write (Data Warehouse)?	Lecturas más <b>rápidas</b> (penalización en la carga), relación entre entidades es sencilla, datos quedan documentados en la estructura.	integracion-datos
¿Cuáles son las desventajas de Schema-on-Write (Data Warehouse)?	Cambios en el esquema obligan a <b>reprocesar</b>, es complicado mapear datos no estructurados, costoso mantener nivel de detalle atómico para volúmenes altos.	integracion-datos
¿Cuáles son las ventajas de Schema-on-Read (Data Lake)?	Volcados más <b>rápidos</b>, flexibilidad para leer según la vista que interese, apropiado para datos no estructurados, permite guardar nivel de detalle atómico.	integracion-datos
¿Cuáles son las desventajas de Schema-on-Read (Data Lake)?	Penalización en la <b>lectura</b>, no hay documentación clara de los datos, necesita alta capacidad de proceso, más dificultades para data governance y seguridad.	integracion-datos
¿Qué es ETL (Extract, Transform, Load)?	Proceso de flujo de datos en 3 etapas:<br><b>Extract:</b> consultar y extraer del sistema origen<br><b>Transform:</b> limpiar, normalizar y procesar<br><b>Load:</b> almacenar ya transformada en el destino	integracion-datos
¿Qué es ELT (Extract, Load, Transform) y en qué se diferencia de ETL?	Mismo objetivo que ETL pero <b>distinto orden</b>:<br><b>Extract:</b> extraer del origen<br><b>Load:</b> almacenar <b>cruda</b> en el destino<br><b>Transform:</b> limpiar y procesar en el destino.<br>Asociado a Data Lakes y schema-on-read.	integracion-datos
¿Cuáles son los componentes principales de un Data Warehouse?	<b>Almacenamiento</b> (RDBMS en capas), <b>pipelines de ETL</b>, <b>capa de metadata</b>, <b>data marts</b> (consulta para casos específicos), y <b>capa de presentación</b> (análisis y reporting).	integracion-datos
¿Cómo se lee el flujo de datos en un plan de ejecución de SQL Server?	De <b>derecha a izquierda</b> en el diagrama. El porcentaje en cada operador indica su <b>costo relativo</b> dentro del plan total.	optimizacion-sql
¿Por qué una Heap en SQL Server no soporta Seek?	Porque una heap es una tabla <b>sin índice clustered</b>, sus datos no tienen orden. Sin estructura de índice, solo es posible hacer un <b>Table Scan</b> (recorrer todo).	optimizacion-sql
¿Qué pasa en SQL Server si se pide un ORDER BY/GROUP BY pero los datos no están ordenados por un índice?	El optimizador puede: insertar un operador <b>Sort</b> explícito + Stream Aggregate, o usar <b>Hash Aggregate</b> (que no necesita orden) + Sort al final si se requiere orden en output.	optimizacion-sql
¿Qué tipos de Data Catalogs existen?	<b>In-house:</b> construidos internamente (Uber Databook, Airbnb, Netflix).<br><b>Third-party:</b> herramientas comerciales o cloud (Google, AWS, Azure).<br><b>Open Source:</b> Amundsen (Lyft), Apache Atlas, Magda, CKAN.	privacidad-compliance
